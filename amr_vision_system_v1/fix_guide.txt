Section 1 — Critical Bugs (Fix Immediately)
These bugs cause crashes, silent misconfigurations, or resource exhaustion in production. Fix before any other work.
Bug 1.1 — Missing Optional Import in detection/types.py
SEVERITY: CRASH ON IMPORT
File:  detection/types.py
Root Cause: The Detection dataclass uses Optional[str] for the color field but Optional is never imported from typing. Any module that imports Detection will raise a NameError at startup.
Fix — Change this line:
# BROKEN — missing Optional
from typing import Any, Dict, List, Tuple
# FIXED
from typing import Any, Dict, List, Optional, Tuple
Verify the fix by running:
python -c "from detection.types import Detection; print('OK')"
Bug 1.2 — Hardcoded Confidence Floor in hybrid_detector.py
SEVERITY: SILENT MISCONFIGURATION
File:  detection/hybrid_detector.py, Line 88
Root Cause: Even though confidence is read from config (e.g. 0.03), a hardcoded filter on line 88 silently drops all detections below 0.5. Users who lower the config value see no change in behaviour.
Fix — Replace line 88:
BEFORE (broken)
dets = [d for d in dets if d.confidence >= 0.5]
AFTER (fixed)
dets = [d for d in dets if d.confidence >= self.confidence]
After fix: set detection.confidence: 0.03 in config.yaml and confirm low-confidence detections appear in output.
Bug 1.3 — Dead DuplicateResolver Instance in main.py
SEVERITY: DEAD CODE / ARCHITECTURAL CONFUSION
File:  main.py, Line 83
Root Cause: A DuplicateResolver is instantiated as resolver but never used. The DetectionFuser already creates its own internal resolver. Two solvers are alive simultaneously; the external one is orphaned.
Fix Option A — Remove the orphaned instance (recommended):
# DELETE this line from main.py
resolver = DuplicateResolver()   # line 83 — remove entirely
fuser = DetectionFuser()         # keep this — it has its own resolver
Fix Option B — Pass resolver into fuser (for external control):
resolver = DuplicateResolver()
fuser = DetectionFuser(resolver=resolver)  # inject it
# Remove the inline resolver from DetectionFuser.__init__
Bug 1.4 — PoseEstimator Ignores postprocess.enabled Flag
SEVERITY: ARCHITECTURAL INCONSISTENCY
File:  main.py (setup + main loop)
Root Cause: post is set to None when postprocess.enabled: false, but pose_estimator is created and called unconditionally regardless. The config structure implies disabling postprocess disables all sub-steps.
Fix — Gate pose estimator creation and usage under the post check:
# Setup
post = PostProcessor(post_cfg) if bool(post_cfg.get("enabled", True)) else None
# FIXED: only create pose_estimator when postprocess is active
pose_estimator = None
if post is not None:
pose_cfg = post_cfg.get("pose") or {}
pose_estimator = PoseEstimator(pose_cfg)
# In main loop:
if pose_estimator is not None:
det_dicts = pose_estimator.estimate_pose(det_dicts, warped_frame)
Bug 1.5 — Main Loop Spins at 100% CPU on Frame Failure
SEVERITY: RESOURCE EXHAUSTION
File:  main.py (main loop)
Root Cause: When the camera returns ok=False (USB disconnect, brief failure), the loop retries immediately with no sleep. This saturates one CPU core indefinitely.
Fix — Add a short sleep before retrying:
BEFORE (broken)
if not ok or frame is None:
continue   # tight spin
AFTER (fixed)
if not ok or frame is None:
time.sleep(0.01)  # 10 ms
continue
Also ensure time is imported at the top of main.py (it is imported but time.sleep is never called — this is the first use).
Bug 1.6 — Unbounded In-Memory Output Buffer
SEVERITY: OUT OF MEMORY — LONG SESSIONS
File:  main.py (output section)
Root Cause: When output.append: false, every frame payload is appended to output_history in RAM and only written on program exit. A long-running robot session will OOM.
Fix Option A — Change the default to append mode (recommended for robots):
# config.yaml
output:
append: true   # was false — change default
Fix Option B — Flush the buffer periodically (keep append: false):
FLUSH_EVERY = 500  # frames
output_history.append(payload)
if len(output_history) >= FLUSH_EVERY:
export_output(output_history, out_cfg)
output_history.clear()
Section 2 — Design & Architecture Issues
These are not crash-level bugs but cause incorrect behaviour, confusion, or wasted computation. Fix after critical bugs.
Issue 2.1 — README Does Not Match the Codebase
File:  README.md
The README states the project has no tracking, no pose estimation, no fusion. The codebase has all of these. Completely rewrite the README. At minimum, update the feature list to include: CentroidTracker, TemporalFilter, PoseEstimator, DetectionFuser, DuplicateResolver, OccupancyGrid, ObjectCounter, BoardMapper.
Issue 2.2 — aruco Missing from DuplicateResolver Source Priority
File:  fusion/duplicate_resolver.py
Fix — Add aruco to the priority list:
BEFORE (broken)
self.source_priority = ["yolo", "qr", "color", "contour"]
AFTER (fixed)
self.source_priority = ["aruco", "qr", "yolo", "color", "contour"]
ArUco markers are high-reliability detections and should outrank YOLO. Without this, aruco detections fall through source_priority.index() and raise a ValueError caught as lowest priority.

File:  utils/performance_monitor.py

Option B: Delete the file and remove from utils/__init__.py if listed.
Issue 2.4 — _get_active_objects() Is Dead Code in CentroidTracker

The method is defined but never called. Either:
Rename to get_active_objects() (public) and call it in main.py where the tracker state is read, or
Delete it entirely.
Issue 2.5 — TemporalFilter Prunes State Too Aggressively
File:  tracking/temporal_filter.py
Root Cause: State is pruned to only IDs in the current frame. If an object disappears for one frame (but the tracker keeps it alive for max_disappeared=8 frames), the filter loses its smoothed state immediately. On re-appearance the bbox and confidence snap instead of resuming smoothly.
Fix — Prune based on tracker liveness, not current frame:
# Pass tracker's active IDs to the filter
# In main.py:
tracker_active_ids = set(tracker.objects.keys())
filtered = temporal_filter.update(dets, tracker_active_ids)
# In temporal_filter.py — change prune logic:
def update(self, detections, alive_ids):
# ... existing logic ...
# Prune only IDs no longer tracked:
self.states = {oid: s for oid, s in self.states.items()
if oid in alive_ids}
Issue 2.6 — CentroidTracker Uses Wall Clock for Velocity
File:  tracking/centroid_tracker.py
time.time() is used for dt in velocity computation. In a threaded/polling camera setup, frames arrive at irregular intervals, making velocity noisy.
Fix — Pass frame timestamp into tracker.update():
# main.py — timestamp already computed:
timestamp_ms = now_ms()
objects = tracker.update(dets, timestamp_ms=timestamp_ms)
# centroid_tracker.py — use it:
def update(self, rects, timestamp_ms=None):
now = timestamp_ms / 1000.0 if timestamp_ms else time.time()
dt = now - self.last_timestamp
self.last_timestamp = now
Issue 2.7 — ObjectCounter Resets on Every Frame
File:  perception/object_counter.py
self.reset() is called at the start of every update(), making counts per-frame only. The variable names (total_by_label, unique_tracked) suggest cumulative intent.
Choose one:
Per-frame snapshot (document this): Rename variables to frame_counts_by_label. Add a docstring: 'Returns per-frame counts, not cumulative.'
Cumulative counting (remove reset): Delete the self.reset() call from update(). Add a public reset() method for callers to invoke when a new session begins.
